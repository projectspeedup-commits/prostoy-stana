# Шлюз «Простои стана»

Python 3.13, Windows 10 x64. Раз в секунду читает настроенные теги OPC UA WinCC или S7,
считает выдачу заготовок и состояние стана, сохраняет события в SQLite, затем отправляет HTTP.
Формат — [CONTRACT.md](CONTRACT.md). С ручными отметками приложение эти события не смешивает.

**Только чтение.** Клиенты не записывают значения, не управляют CPU и не вызывают методы WinCC.
Для OPC UA завод должен выдать учётную запись с правом чтения. Для S7 ограничение реализовано
кодом шлюза; разрешение PUT/GET на CPU само по себе не ограничивает доступ только чтением.

## Установка

Из корня репозитория, PowerShell (Python 3.13 x64 установлен отдельно):

```powershell
py -3.13 -m venv gateway\.venv
gateway\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r gateway\requirements.txt
Copy-Item gateway\config.example.toml gateway\config.toml
Set-Location gateway
.venv\Scripts\python.exe -m stan_gateway check --config config.toml
```

Зависимости закреплены: asyncua 1.1.8, python-snap7 2.0.2. Готовые колёса и их зависимости
для CPython 3.13 / Windows x64 проверяются установкой с `--only-binary=:all:`.
Активация venv не обязательна. Команды ниже выполняются из `gateway/`.

```powershell
.venv\Scripts\python.exe -m stan_gateway run --config config.toml
.venv\Scripts\python.exe -m stan_gateway check --config config.toml
.venv\Scripts\python.exe -m stan_gateway send-test --config config.toml
.venv\Scripts\python.exe -m stan_gateway queue-stats --config config.toml
.venv\Scripts\python.exe -m stan_gateway simulate-server --config config.toml --port 4862
```

`check` читает один раз и выводит «тег / значение / качество», код 0 — все значения хорошего
качества, 1 — ошибка/плохое качество. Очередь не изменяет, ничего не отправляет.
`send-test` сначала сохраняет один heartbeat, делает одну попытку, печатает ответ; код 0 только
при HTTP 200. При ошибке событие остаётся в очереди либо в `rejected`.
Ctrl+C/SIGTERM останавливают цикл, закрывают источник и сохраняют очередь; текущий HTTP может
завершаться до 15 секунд. Автозапуск Windows этой программой не настраивается.

## Конфиг и секреты

Описание каждого поля — [config.example.toml](config.example.toml). Пути относительно TOML.
`source`: `opcua`, `s7` или встроенный `simulator` без сети. Теги: `name`, `address` (для S7),
`type` (`bool`, `int`, `real`), `watch`, `deadband`. Порог применяется к последнему отправленному
значению: изменение должно быть **больше** порога. Первое хорошее значение после подключения
отправляется всегда; плохие/нечисловые/NaN значения не участвуют в событиях и правилах.

Ключ берётся из `STAN_GATEWAY_KEY`, затем из `server.key_file`. Пароль OPC UA — из
`opcua.password_env` (по умолчанию `STAN_OPCUA_PASSWORD`) или `opcua.password_file`.
В файле секрета — одна строка. Значения секретов в TOML запрещены; не храните их в Git.
Ограничьте доступ к отдельным файлам средствами `icacls` своей учётной записи.
HTTP вне localhost запрещён. HTTPS проверяет цепочку сертификата и имя сервера;
HTTP-перенаправления не выполняются, чтобы не передать ключ другому адресу.

Выдача: устойчивый передний фронт `sensor_tag == true AND status_tag == status_value`.
`debounce_ms` подавляет краткие изменения обоих уровней. Первая выборка после подключения
задаёт базу: запуск во время уже активного датчика не создаёт повторную заготовку.
`mill_state`: `unknown` после запуска (не отправляется), `running` после выдачи,
`stopped` после `minutes` без выдачи. До первой заготовки таймер идёт с первого хорошего чтения.
При потере связи/качества таймер сбрасывается: это время не доказывает простой.

## Журнал и очередь

`data_dir/logs/gateway.log`: по-русски, 5 МБ + 10 архивов, секреты скрываются.
`data_dir/queue.db`: SQLite WAL, транзакция фиксируется до отправки, UUID сохраняется при повторе.
До 100 событий и 60 КБ полного UTF-8 JSON в запросе, таймаут 15 секунд. HTTP 200 удаляет пачку;
401/429/5xx/сеть дают паузы 5, 10, 20…300 секунд. 400/413 делят пачку; непринимаемый одиночный
UUID и ответ остаются в таблице `rejected`, повторно не отправляются.

Лимиты действуют на очередь **и rejected вместе**: 30 суток по времени события, 200 000 записей.
Старше 30 суток удаляются все типы; при превышении количества первыми вытесняются старые
`signal`, затем `heartbeat`, последними `billet_out`/`mill_state`/`source_state`.
Это единственная предусмотренная потеря событий; удаления отмечаются в журнале.
При длительном отсутствии сервера выгрузите нужные события до истечения 30 суток.

## Проверка на имитаторе

В `config.toml` оставьте локальный `opcua.url`, переключите `source = "opcua"`.
В первом окне запустите `simulate-server`, во втором — `check`, затем `run`.
Имитатор слушает только `127.0.0.1`, создаёт те же имена и NodeId по шаблону WinCC.
Заготовка каждые 40–90 с, активный датчик 3–6 с, иногда перерыв 3–15 минут.
Без локального HTTP-приёмника/ключа отправка будет отложена, события останутся в SQLite.
`--speed 10` ускоряет цикл имитатора; для коротких импульсов ускоренного интеграционного теста
тестовый код также уменьшает период чтения. В обычном `run` период всегда 1 с.

Тесты из корня репозитория (только unittest, сеть только loopback):

```powershell
gateway\.venv\Scripts\python.exe -m unittest discover -s gateway/tests -v
```

## Что нужно от завода

OPC UA: версия WinCC, наличие OPC UA/Connectivity Pack, адрес и порт, точные NodeId/namespace,
режим безопасности и учётная запись чтения. По умолчанию `ns=1;s=t|{tag}` и `None`.
Для `Basic256Sha256` используется `SignAndEncrypt`: сертификат и закрытый ключ клиента,
сертификат клиента в доверенных WinCC, доверенный сертификат сервера при необходимости.
Пароль — только окружение/отдельный файл. NodeId вне стандартного шаблона согласовать с инженером.

S7: модель CPU, IP, rack/slot, доступ по TCP 102, список DB/адресов и типов.
Для S7-1200/1500 инженер проверяет разрешение PUT/GET и доступ к DB без оптимизации.
Шлюз читает близкие адреса одной области/DB пачками; DBW трактуется как знаковый INT,
DBD — DINT или REAL по конфигу. Q читается как область выходов, записей в неё нет.
Несколько CPU обслуживаются отдельными процессами с разными TOML, `gateway_id` и `data_dir`.
Завод также подтверждает два тега выдачи, норму времени простоя, синхронизацию часов ПК (Москва),
разрешение на пилот и исходящий HTTPS к приложению. Доступ к заводу локальными тестами не проверяется.
