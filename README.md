# Учёт простоев стана

Простой ввод простоев оборудования: рабочий нажимает «Стан встал», выбирает причину плиткой и нажимает «Стан пошёл». Время ставит система.

## Как устроено

- `app/core` считает смены, производственные сутки и сводки. Один и тот же код исполняют страница и сервер.
- `app/server` принимает нажатия, хранит базу и отдаёт страницу.
- `app/public` содержит страницу рабочего. Она открывается без сети и досылает нажатия, когда связь вернётся.
- `bridge` передаёт копию данных без фамилий в Google Таблицу.
- `deploy` содержит образцы для запуска в Docker.
- `legacy` хранит исходный скрипт формы, с которого начинался проект.

## Запуск проверок

```bash
npm test
```

## Запуск в Docker

```bash
docker compose -f deploy/compose.yaml up -d --build
```

## Настройки администратора

`GET /api/admin/settings` возвращает расписание двух смен, мастеров (ФИО, смена, телефон), контакты и `refsVersion`. `PUT` принимает `{refsVersion:"версия из GET",settings:{schedule:{shifts:[{no:1,start:"08:00"},{no:2,start:"20:00"}]},people:[],contacts:[]}}`. Конец каждой смены — начало следующей; шаг времени 30 минут, длительность каждой не менее часа. Новый мастер передаётся с пустым `id` или `null`, сервер назначает идентификатор.

Оба запроса требуют обычный ключ устройства `X-Device-Key` и входят в общий лимит 60 запросов в минуту. Отдельного пароля администратора пока нет. Ошибки проверки возвращают `400` с русским `message`, тело больше 64 КБ — `413`. При устаревшем или отсутствующем `refsVersion` сервер возвращает `409` с сообщением об изменениях на другом устройстве; форму нужно обновить.

Настройки хранятся в `<STAN_DATA_DIR>/settings.json` (по умолчанию `./data`, в Docker — `/app/data` на постоянном томе). Запись атомарная, предыдущий файл сохраняется в `settings.json.bak`. При наличии настроек они имеют приоритет над `STAN_PEOPLE_FILE`; без файла остаются прежние люди и расписание, телефоны пустые. Новое расписание используется сразу, сохранённые события не переписываются. В `?mock=1` изменения живут в памяти вкладки до перезагрузки.

Повреждённые настройки не останавливают API: используется последний исправный снимок в памяти, затем `settings.json.bak`, затем справочник людей или демо. `/api/health` возвращает `settings: "ok"` или `"fallback"`. Сохранение через администратора восстанавливает основной файл; повреждённая копия сохраняется отдельно и не вытесняет исправный `.bak`.

События принимаются за последние 40 суток; ручной простой — не более 7 суток, брак — 0–1000 тн. Очередь планшета хранится отдельно от квитанций и отправляется по порядку пачками до 50 событий / 40 КБ JSON. Подтверждённые квитанции хранятся до 3 суток и не более 300, метаданные цепочек исправлений сохраняются у ожидающих записей.

`npm test` включает браузерную проверку, если доступен Chrome (путь можно задать через `STAN_TEST_CHROME`). `node tests/smoke.mjs` запускает отдельный сервер на `127.0.0.1:8299`, проверяет HTTP-сценарии и останавливает его. Данные и снимки — в игнорируемой папке `private` текущего worktree.

## Чего в репозитории нет

Фамилий, ключей, адресов серверов и настроек боевой среды. Они лежат в папке `private` и в файле `.env`, которые в git не попадают.
