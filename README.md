# Учёт простоев стана

Простой ввод простоев оборудования: рабочий нажимает «Стан встал», выбирает причину плиткой и нажимает «Стан пошёл». Время ставит система.

## Как устроено

- `app/core` считает смены, производственные сутки и сводки. Один и тот же код исполняют страница и сервер.
- `app/server` принимает нажатия, хранит базу и отдаёт страницу.
- `app/public` содержит страницу рабочего. Она открывается без сети и досылает нажатия, когда связь вернётся.
- `bridge` передаёт копию данных без фамилий в Google Таблицу.
- `deploy` содержит образцы для запуска в Docker.
- `legacy` хранит исходный скрипт формы, с которого начинался проект.

## Настройки администратора

`GET /api/admin/settings` возвращает расписание двух смен, мастеров (ФИО, смена, телефон), контакты и `refsVersion`. `PUT` принимает `{settings:{schedule:{shifts:[{no:1,start:"08:00"},{no:2,start:"20:00"}]},people:[],contacts:[]}}`. Конец каждой смены — начало следующей; шаг времени 30 минут, длительность каждой не менее часа. Новый мастер передаётся с пустым `id` или `null`, сервер назначает идентификатор.

Оба запроса требуют обычный ключ устройства `X-Device-Key` и входят в общий лимит 60 запросов в минуту. Отдельного пароля администратора пока нет. Ошибки проверки возвращают `400` с русским `message`, тело больше 64 КБ — `413`.

Настройки хранятся в `<STAN_DATA_DIR>/settings.json` (по умолчанию `./data`, в Docker — `/app/data` на постоянном томе). Запись атомарная, предыдущий файл сохраняется в `settings.json.bak`. При наличии настроек они имеют приоритет над `STAN_PEOPLE_FILE`; без файла остаются прежние люди и расписание, телефоны пустые. Новое расписание используется сразу, сохранённые события не переписываются. В `?mock=1` изменения живут в памяти вкладки до перезагрузки.

## Отчёт в Excel

`GET /api/report.xlsx?from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД` отдаёт книгу .xlsx за производственные сутки (от начала Смены 1, по МСК), обе даты включительно. Нужен ключ устройства `X-Device-Key`. Листы: «Сводка», «По сменам», «Журнал простоев», «Приём и сдача смен»; итоги сводки считает то же ядро, что экран «Показатели стана», время после «сейчас» не считается. Неверный период возвращает `400` с русским `message`: даты корректны, `from` не позже `to`, `to` не позже текущих суток, не больше 92 суток. Книгу собирают `app/core/report.js` и `app/core/xlsx.js` (без зависимостей, в Node и в браузере), маршрут — `app/server/report.js`, кнопка и панель периода — `app/public/report-ui.js`. В демо (`?mock=1`, GitHub Pages) отчёт строится в браузере из демо-событий.

## Чего в репозитории нет

Фамилий, ключей, адресов серверов и настроек боевой среды. Они лежат в папке `private` и в файле `.env`, которые в git не попадают.
